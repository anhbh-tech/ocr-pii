# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Test: `uv run --extra dev pytest -q`. Standard library only, Python ≥ 3.11.
- **Synthetic data only.** Never commit a real client document, name or value. `tests/test_synthetic_only.py` scans every tracked or unignored file. It allows e-mail only at `example.*`/`vidu.test` and phone or ID digits only in the reserved invented shapes (see `tests/fixtures/README.md`). Widen that allow-list only for invented values.
- **The roster is runtime data** (`--roster` / `PII_CORE_ROSTER`). It says whose a name is: `FIRM` (the firm's own staff, kept), `PARTY` and `AGENCY` (tokenised under the roster name since the 2026-09-28 rulings). With no roster every internal name is tokenised as a client's. Keep the real file outside the repo (`~/.private/pii-core/roster.json`, 0600); `serve` warns when it is empty. pii-lab's `parties.py` names real public counterparties. Do not port those names or any real matter code; tests use `tests/fixtures/roster_synthetic.json`.
- **pii-lab's decision model is the source of truth.** Actions come from `src/pii_core/data/evidence.json` through `decide.py`. Change an action by changing the evidence and citing its basis, never by special-casing. `docs/RECONCILIATION.md` records every disagreement with ocr-lab `pii.js` and every L that departs from pii-lab; `PII_LAB_ACTIONS` in `tests/test_decide.py` stays pii-lab's frozen table; an action that departs from it goes in `DEPARTURES` beside it, with its basis in RECONCILIATION.
- Tokens are byte-compatible with pii-lab: the same HKDF info labels (`pii-lab/v1/...`) and the same `CATEGORY|flatten(value)` input. Renaming them breaks the joins between the two tools. Procedural dates are tokens over their ISO form, not shifted (2026-09-28, P1); dates of birth are `BIRTH_DATE`, anonymised. Tokens carry no interval, so deadline and stage arithmetic must run on real dates in the trusted zone. The shift survives only to restore legacy vaults.
- The 2026-09-28 rulings (P1–P4, and the image rows `image: true`) are recorded in `docs/RECONCILIATION.md`, *The firm's rulings of 2026-09-28*. `POST /v1/case` is `redact_case` over HTTP: use it, not per-document calls, when a case's documents are masked together.
- The service binds loopback only; the default is 127.0.0.1:8813, and pii-lab uses 8812. `server.check_host` refuses any other address, and it must keep doing so.
- The key comes only from `PII_CORE_KEY`, `PII_CORE_KEY_FILE` or `--key-file`, never a default. The vault (`*.vault.json`, git-ignored) holds originals. The audit (`fields`, `--json`) must never hold one; `test_the_audit_carries_no_original_value` guards this.
- Person names live in `names.py`: four layers switched by `names.LAYERS`. `tests/name_bench.py` measures them (`dev` is the tuning set; `holdout` was never tuned against, so keep it that way and report it). A propagated variant maps to its canonical name through `Hit.canonical`, so one person gets one token. Names the case's own documents give (`names_seen`) are sought again in every shape; vault PERSON values only as guesses (`names_guessed`: a name's casing, the accents seen), since a vault row may be a misread phrase. Vault MARK, MATTER_REF and ORG values are sought again too (`marks_seen`, `refs_seen`, `orgs_seen`); an ORG by its name without the legal form (`extract.org_hits`), every writing of one firm under one token (`org_forms`). `names.COMMON` (common nouns such as "Đơn", which stop a PERSON from starting) must never hold a name syllable; `test_the_common_words_are_no_name_syllable` guards this.
- **The residue sieve stays fail-closed.** `document.RESIDUE_DIGITS` stops a document over any untreated run of 9+ digits. When it fires, teach the recognizer the number kind (a detector, a label rule, a cue word); never widen the sieve's own exceptions. The four kinds the 2026-09-24 dry run found are in `docs/RECONCILIATION.md`, *The two number kinds the dry run forced*; the ones the 2026-09-25 real-case replay added, and what it left open outside pii-core, are in `docs/GAPS.md`. Text whose PDF font map is garbled is stopped too (`RESIDUE_GARBLED`): it needs OCR, not a detector.
- **The caller's own facts are `case_vars`** (`casevars.py`, `--var` / `--vars-file`, `"vars"` in `POST /v1/document` and `/v1/case`). Matching is on a folded form over whole words, with one edit tolerated for a letters-only whole value and never for one holding a digit. A caller that matches case variables by exact string will leak the joined, unaccented and mistyped shapes.
- Extraction precedence lives in `extract.resolve`: tokens already in the text are blocked first (never re-tokenised), then roster hits, then exact patterns, then labelled fragments, then the captions a flattened table row puts beside a value (`Nationality:` after a name), then KEEP shields, then heuristics; last, `_birth_dates` relabels a DATE under a birth label or after a birth cue as BIRTH_DATE. Span sets stay sorted and non-overlapping, so the overlap checks can use bisect. Keep them that way, or large documents turn quadratic.
